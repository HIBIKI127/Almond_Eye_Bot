# Almond Eye Bot

Java 17 / Spring Boot QQ 聊天机器人。保留 QQ 官方开放平台接口，新增 **OneBot v11 反向 WebSocket** 接入，使用 NapCat 登录的 QQ 账号收发私聊和群消息。

## 主要功能

1. **自动聊天是核心功能**：私信和明确开启的群聊中，直接发送“我想吃什么”等普通文本即可通过模型 API 对话，无需 @、斜杠命令或 AI 关键词。
2. **关键词回复优先**：聊天中命中已启用规则时，回复配置的文字或图片，不再额外调用模型。可配置完全一致或包含关键词。
3. **附加功能暂不使用**：首次升级会停用旧 AI 指令、Wiki、帮助和清除历史规则，保留数据供以后显式启用；Wiki 总开关同时关闭。已有固定回复及图片关键词保留。

群聊仍须先配置并开启；AI 总开关、冷却、每日次数、输入输出及上下文限制继续生效。模型只发送最终结果，失败或空响应不发消息。

## 网页配置中心

启动项目后，浏览器访问 **[http://localhost:8080/admin/](http://localhost:8080/admin/)**。页面与后端一同打包，不需要安装 Node.js，也不需要单独启动前端。修改 `SERVER_PORT` 后请使用对应端口。

- **关键词回复**：管理固定文字与图片关键词；附加动作保留为可选配置，自动聊天不依赖规则。每条规则选择“执行动作”，可修改关键词、提示文字、匹配方式、优先级和启停。优先级为 0–999，数值越大越先匹配；相同优先级按创建顺序，每条消息只执行首条命中规则。新建规则默认优先级 10，迁移规则为 0。
- **图片资源**：支持选择或拖入多张 PNG、JPEG、GIF；每张最大 10MB、2000 万像素。文件内容会经过图片验证，不能只修改扩展名上传。正在被规则引用的图片不能直接删除。
- **功能设置**：切换关键词回复、AI、Wiki和内置图片。修改自动保存，下一条消息生效。
- **人设配置**：在侧栏“人设配置”先选择范围：某个群（机器人QQ＋群号）或“私聊 / Web 默认人设”，再编辑名字、性格、爱好、自我认知、情绪和口癖。各群独立保存，修改一个群不影响其他群或私聊，下一次请求生效；固定关键词回复不受影响。最多8000字符，留空使用内置默认人设，不继承私聊或其他群；“填入示例”需手动保存。人设保存在数据库并包含在SQL导出中，越长越占用模型输入Token。
- **内容边界**：在人设配置页下方独立编辑全局“禁止回复内容”，最多8000字符，适用于所有群、私聊与Web的AI生成回复，优先于人设、历史记忆和学习表达；单独保存、清空及数据库持久化，包含在SQL备份中。保存后新请求立即使用新规则，在途旧规则结果会丢弃。旧人设不会自动拆分，可手动迁移限制条目；此配置是模型指令，不保证绝对拦截，也不影响固定回复和图片发送。
- **群聊管理**：每群一个机器人总开关。必须配置并开启后才处理关键词、图片、查询和 AI；关闭后也会抑制仍在等待的 AI / Wiki 回复。
- **回复测试**：固定回复可预览文字和上传图片；功能规则显示匹配动作和提取参数。不会调用 AI / Wiki、清除历史或发送真实 QQ 消息。
- **导出 SQL**：下载当前设置、资源元数据和规则的 `.sql` 文件。图片文件需另行备份。

触发关键词全部从数据库读取，消息处理代码不再保留内置命令分支。OneBot WebSocket、HTTP 兼容入口、官方 QQ 私聊和 Web 聊天共用规则匹配与动作执行器。群聊总开关在关键词匹配之前检查；私聊不受群开关影响。官方 QQ 群的 OpenID 尚未映射到本项目的 QQ 数字群号配置，因此不会绕过群许可执行功能；当前群聊继续使用 NapCat / OneBot。

### 关键词数据库迁移

首次启动新版会给旧 `reply_rule` 表补充 `action_type` 列，旧规则默认为固定回复，再将原有命令写入数据库。已有同名关键词保留原规则，不覆盖文字、图片、开关或优先级。迁移记录保存在 `bot_migration` 表，后续启动不会恢复你已删除的默认规则。SQL 导出同时包含动作字段和迁移记录，恢复后也不会重复初始化默认词。

自动聊天无需在关键词页配置 AI 规则。若以后显式启用附加的“AI 指令”或“Wiki 查询”规则，可配置任意触发词。它们自动匹配“关键词＋空格＋详细内容”；包含匹配允许关键词出现在长句中，完全一致要求从关键词开始。参数提示可使用 `{keyword}`，改名后自动代入新词。英文功能词不区分大小写；固定回复仍区分大小写，纯英文关键词使用词边界，避免短词误匹配其他单词。帮助动作从已启用且功能开关允许的规则生成功能列表。

停用或删除一条规则后，该关键词不会再通过代码中的后备命令触发。未命中关键词的普通消息直接进入模型对话，旧 SMART / KEYWORD 模式不再筛选消息。功能设置中的“关键词自动回复”控制固定文字和上传图片规则；AI、Wiki、随机图片分别受对应功能开关控制。

页面默认仅允许从本机 `localhost` / `127.0.0.1` 访问管理接口。本机无需登录；需要远程管理时，启动前设置 `BOT_ADMIN_TOKEN`，再在页面左下角“连接设置”输入相同值。管理 Token 只在当前浏览器会话中保存，不进入 SQL 导出；通过公网访问时请使用 HTTPS。

```powershell
$env:BOT_ADMIN_TOKEN = '替换为自己的随机长字符串' # 仅在需要鉴权时配置
.\mvnw.cmd spring-boot:run
```

页面“已连接”指配置服务可访问，QQ 是否在线仍需用 `ping` 验证。QQ / OneBot 连接地址、Token、AI API Key 继续通过环境变量配置，页面不读取或暴露这些密钥。

### 人设切换与已有对话

保存人设后，所选范围已有会话的下一次AI请求使用新人设，无需清除当前范围的历史或重启。各群独立，私聊/Web默认人设单独管理。旧机器人回答及个人摘要以明确标记的历史参考数据提供，不再作为assistant风格示例；当前人设优先于历史身份、语气与口癖。群语言学习仍仅为本群低优先级参考，不修改核心人设。

群人设存于 `group_persona`，按“机器人QQ＋群号”保存prompt和revision；修改此群会增加修订号。生成期间当前群人设变化，旧结果被丢弃，不追加个人记忆；即使文本先改掉再改回，修订号也能识别旧任务。修改其他群或私聊不会中断本群回答，已消耗额度与冷却保持，已提交发送的消息不撤回。私聊继续检查其独立默认人设。

升级时只执行一次迁移：把原共用人设复制为各已有群的独立初始值，不改原私聊配置。以后新增/发现的群使用内置默认，不随私聊人设变化。群内个人记忆也改为“机器人QQ＋群号＋用户QQ”隔离，防止同一用户将另一群角色对话带进来；旧共享个人记录无法可靠分群，因此保留原数据但不复制到新群记忆。既有本群群聊时间线保持。更新前停服备份data/uploads，新JAR启动自动建表并迁移；请勿手动删除 `group_persona_v1` 标记，否则会重新尝试初始化缺失群配置。

管理API：`GET/PUT /admin/api/groups/{机器人QQ}/{群号}/persona`读取/保存该群人设，PUT提交 `{"prompt":"你叫小杏，温柔简洁。"}`，需先存在对应群配置；`GET/PUT /admin/api/persona`仅管理私聊/Web默认人设。沿用管理鉴权及PUT的 `X-Requested-With: AlmondAdmin` 来源头。页面切换范围会确认未保存草稿，读取失败禁止保存；群人设和修订号随SQL导出恢复。删除群配置会级联删除其人设，重新添加不会恢复旧人设；历史聊天记录不自动删除。模型风格效果仍需实际观察。

### Tag 关键词搜图

发送 `搜图 hatsune_miku` 或 `搜图 hatsune_miku blue_hair`，机器人通过 Danbooru 兼容的 `/posts.json` API 随机检索并发送一张图片和原帖链接，不调用 AI、不消耗群 AI 次数。单独发送 `搜图` 查看用法。需要站点已有 tag，词内用下划线、多个 tag 用空格分隔，最多两个（支持 `-tag` 排除，至少一个正向 tag）；不自动将中文角色名翻译为 tag，不支持分级、排序、OR 等高级搜索语法。

首次升级自动新增“搜图”规则（完全一致、优先级 20、`TAG_IMAGE` 动作）。已有同名规则不覆盖；在管理页“关键词回复”可改名、停用、删除，或新建“Tag 关键词搜图”动作。删除后重启和恢复新版 SQL 都不会自动补回。明确命中此动作时优先于资料库检索；其他规则的优先级仍按原规则系统执行。

功能独立于 AI、Wiki、内置图片和固定关键词总开关；群聊总开关及普通群消息回复率仍生效，@机器人跳过概率。管理页的回复测试仅显示动作与参数，不实际访问图片站。

| 环境变量 | 默认值 | 用途 |
| --- | --- | --- |
| `IMAGE_SEARCH_ENABLED` | `true` | 关闭后不访问图片站，并回复功能已关闭 |
| `IMAGE_SEARCH_BASE_URL` | `https://danbooru.donmai.us` | Danbooru 兼容 API 的 HTTPS 站点根地址 |
| `IMAGE_SEARCH_IMAGE_HOSTS` | `cdn.donmai.us` | 额外允许下载图片的精确主机名，多个以逗号分隔；API 同主机始终允许 |
| `IMAGE_SEARCH_PROXY_URL` | 空 | 可选 HTTP 代理，如 `http://127.0.0.1:7897`；用于 API 和图片下载，不支持 SOCKS 或带凭据的代理 URL |
| `IMAGE_SEARCH_LOGIN` | 空 | 可选站点用户名 |
| `IMAGE_SEARCH_API_KEY` | 空 | 可选站点 API Key，必须与用户名一起设置；只发送到 API，不发往图片 CDN |
| `IMAGE_SEARCH_COOLDOWN_SECONDS` | `5` | 全机器人共享搜图冷却，最少 1 秒，失败请求同样计冷却 |

只检索并二次核验 `rating:g`（General）结果，跳过已删、被封禁、待审或被标记的帖子；站点分级由站点提供，不是独立图像审核保证。不允许用户通过搜索词改写分级。每批最多取 20 个候选，遇到近期重复图片时最多取 3 批随机结果，单次最多尝试下载 3 张，每次只发一张；仅支持 JPEG/PNG/GIF，最多 8MB、首帧 2000 万像素，下载后验证图片可解码。无合适结果、站点失败、限流时返回文字提示，不转入 AI。

**随机去重**：继续按站点随机顺序选择，但跳过当前聊天目标最近选取的图片。相同机器人在同群的所有成员共享记录；不同群、不同私聊和不同机器人账号互不影响，Web 会话独立。记录不依赖 tag 文本，因此换 tag 或调整 tag 顺序也不会绕过；以站点及有效 MD5 识别图片，缺少 MD5 时使用帖子 ID。同一 MD5 的多个帖子也会去重，不识别裁切、重编码等视觉相似图片。

每个目标最多保留 200 张、最长 7 天，全局最多 10000 条，超出后淘汰最旧记录。记录保存在 H2 的 `tag_image_history` 表，重启保留；SQL 配置导出不携带此运行记录，恢复 SQL 时清空。可用候选都在记录中时返回提示，不自动清空记录或发送重复图；这只是本次有限随机候选没有命中，不代表站点全部图片已经看完。

去重记录在下载和图片校验成功后写入，下载失败不记入。现有 QQ 发送链路未等待最终 action 成功回执，所以记录代表“已选取准备发送”，并非确认送达；群开关中途关闭或发送失败也可能留下记录，之后会按上述容量/期限自动淘汰。

API 响应最多 1MB，只下载 HTTPS 标准端口且处于允许主机名单的图片，不跟随重定向。请求连接超时 5 秒、读取超时 10 秒；图片以 Base64 发送，不保存到上传图片资源库。首次使用需要运行环境能访问 API 和图片 CDN；403/429、账号权限或非兼容站点会影响可用性。此实现不通用支持 Gelbooru、其他不同 API 协议或自动故障切换。

配置修改需要重启后生效；用户名/API Key 仅从环境读取，不写入 SQL 导出。既有模型密钥配置与本功能独立。

如本机浏览器通过代理才能访问图片站，Java 不一定自动沿用终端/浏览器的代理设置；可显式设置 `$env:IMAGE_SEARCH_PROXY_URL = 'http://127.0.0.1:你的代理端口'` 再启动机器人。

### 群表达与黑话学习

部署开关 `GROUP_LEARNING_ENABLED` 默认true；管理页“人格学习”另有即时生效、重启保留的全局和单群学习开关（升级初始均开启）。只有这些学习开关、AI总开关和群聊总开关均开启时才生效。机器人从群成员的新消息中学习多人反复使用的表达短语和黑话，按“机器人QQ＋群号”隔离；核心人设不被写入或替换。回复时只将风格作为辅助参考，黑话仅在当前问题包含对应词时注入；私聊不使用群风格。现有个人/群聊记忆仍独立运行。

低频规则固定为：至少40条有效样本、至少3位成员；每5分钟检查一次，单后台线程每轮最多处理1批，每批最多60条、每条最多160字符。每群两次尝试至少间隔6小时，全机器人每天最多4批、全局两次尝试至少间隔30分钟。每天按北京时间计算；学习额外占用该群每日AI调用额度，但不触发普通回复冷却。失败、截断或无有效候选也计入学习尝试，不高频重试；仅基于群样本、不调用联网搜索；默认开启深度思考，使用JSON输出模式，答案基础预算2048 Token，加4096思考预算，总生成上限6144 Token。

候选仅在内存保存：最多100个群、每群80条，24小时过期；过滤自身消息、匹配到的回复规则/命令、链接、媒体占位和部分明显指令。其他机器人若被QQ当作普通成员消息上报，无法可靠自动识别。去重范围是“同成员＋同文本”。表达需至少2位成员使用原文短语；黑话需至少2位成员、3条样本支持，含义由模型提取，仍可能存在语义误判。

每群最多保存6条表达和12条黑话，学习档案最多100群，满额不自动淘汰已有档案。档案、修订号及学习限额持久化在现有 `data/bot-config.mv.db`，随配置SQL一起导出；候选样本不另写数据库、重启丢弃，避免增加原始聊天存储。新候选优先合并到旧档案，无新候选时保留旧内容。

管理接口复用现有 `/admin/api/` 鉴权（未设Token仅本机，设Token需Bearer）：

- `GET /admin/api/group-learning/settings`：读取部署开关`deploymentEnabled`、持久化管理总开关`storedEnabled`及两者合成的`enabled`。`PUT`同路径提交 `{"enabled":false}` 可即时关闭所有群的学习和风格引用，保留档案、清除待学样本。部署开关关闭时，页面不能强行开启。
- `GET /admin/api/group-learning/{机器人QQ}/{群号}`：查看结构化表达/黑话、修订号、更新时间、上次尝试、候选数；`groupEnabled`为该群学习开关，`effectiveEnabled`另考虑AI和群聊总开关，`busy`为全局后台状态，时间字段为Unix毫秒。
- `PUT /admin/api/group-learning/{机器人QQ}/{群号}/settings`：提交 `{"enabled":false}` 可即时关闭此群采样、学习和风格引用，内容保留，不改变普通聊天设置。关闭会丢弃本群待学样本。
- `DELETE /admin/api/group-learning/{机器人QQ}/{群号}/entries`：提交 `{"kind":"jargon","key":"开摆","revision":当前档案修订号}` 删除一条黑话；表达使用 `kind:"expression"`、key为example原文。版本过期返回409要求刷新；无此条目返回404。删除仅影响该群的这一条，但会丢弃该群候选并使旧学习批次失效，防止错误内容立即写回；其他条目保留。后续新消息仍可能重新学到同一词，本次不添加永久禁学名单。
- `DELETE /admin/api/group-learning/{机器人QQ}/{群号}`：清除档案和当前内存候选；需 `X-Requested-With: AlmondAdmin`。不改核心人设、不清聊天记忆、不重置限额与冷却，在途结果也不能恢复旧档案。后续新消息仍可重新积累学习。

管理页左侧“人格学习”中，可搜索并选择群，分栏查看表达原文/适用语境和黑话/释义，逐条删除、清空当前群档案，以及控制全局和单群开关。关闭不会删档案，允许在关闭状态下纠错和清空。页面明确显示当前是否生效、候选数和更新时间；只按需读取或手动刷新，不新增后台轮询和模型调用。PUT/DELETE均需 `X-Requested-With: AlmondAdmin`，页面已自动携带。删除/清空有确认弹窗，版本冲突时刷新重试。

管理开关保存在 `learning_settings` 和 `group_learning_settings`，与档案和额度一起纳入SQL导出；新建群默认允许学习，但仍受群聊许可和全局开关控制。关闭后即使马上开启，在途旧批次也不会应用；采样从后续新消息重新积累，额度不重置。已开始的模型网络请求不强制中断，仍可能产生一次在途费用，但结果会被丢弃。已经进入生成阶段的普通聊天回答不会因切换学习开关而取消，下一次请求不再引用已关闭的风格。

仍可设置 `GROUP_LEARNING_ENABLED=false` 并重启作为部署层总开关。切换核心人设时，群语言档案保留，冲突时按核心人设回答。更新前备份data/uploads，启动自动补齐学习档案、限额和开关表，不删除已有数据。回退到不支持管理开关的旧版本前，请先用部署开关停用学习，避免旧代码忽略数据库开关。导入含学习表的SQL请使用新版或预先升级过表结构的数据库。


首次部署前，在 [WG 开发者平台](https://developers.wargaming.net/applications/) 创建应用并设置：

```powershell
$env:WOWS_STATS_APPLICATION_ID = '<自己的 WG application_id>'
# 如需要通过 HTTP 代理访问官方 API，再配置此项；不沿用搜图代理
$env:WOWS_STATS_PROXY_URL = 'http://127.0.0.1:你的代理端口'
```

当前 `wows-stats.enabled` 固定为 `false`，停止查询与后台采集，`WOWS_STATS_ENABLED` 不再控制此配置；修改后重启生效。保留的实现需要WG application_id，不需要玩家登录、账号密码或用户 access_token。

**总体报告**显示账号所有模式总场次，并单独展示累计随机战（`statistics.pvp`，含单野及组队）的场次、胜场、胜率、场均伤害、场均击沉、存活率、K/D、场均经验及官方更新时间。不同模式不混算；经验是官方返回值，可能包含高级账号加成。没有船只权重与 PR 期望值，因此不编造 PR、排名或逐局战绩。

**近期随机战有历史条件**：实测旧官方 `/wows/account/statsbydate/` 返回 `METHOD_NOT_FOUND`，无法回填指定玩家任意过去日期的战绩。项目在每次成功查询时保存累计随机战快照，后续使用当前累计值减去请求起点附近的历史累计值；首次查询一般只能得到总体，近期查询会明确提示“历史快照不足”，不会冒用总体或更短区间。

- 基线必须位于“当前采集时间减 N 天”之前的 2 小时范围内，报告列明实际北京时间区间；这不是逐局日志，也不保证恰好 N×24 小时。官方更新延迟可能进一步影响覆盖范围，报告同时显示其更新时间。
- 开启功能且 application_id 已配置时，程序每 5 分钟检查一批最多 20 个已查询账号，对距上次刷新尝试至少 1 小时的账号采集新累计值。失败只保留旧快照并退避，不伪造更新、不向聊天发送状态。后台采集不延长用户活跃时间，最近 30 天未查询的账号停止采集。
- 每账号每 UTC 小时保留一份最新累计快照，最多跟踪 100 个账号，超额淘汰最久未查询的账号及其快照；快照保留 400 天。服务离线、API 异常、跟踪被淘汰等造成的基线空缺会明确提示不足。统计回退、隐藏战绩、缺字段或异常值不用于伪造差值。
- 相同区服/输入的查询结果在内存缓存 60 秒，未命中缓存的用户请求全局间隔至少 3 秒。后台采集与用户查询均只访问官方公开数据。

报告附带**本地规则生成的辛辣锐评**，根据本次统计范围的胜率及样本量吐槽游戏表现，不使用 AI、不消耗群 AI 次数；高胜率也会附带调侃。零场与少于 20 场单独处理，不把小样本当成实力定论；隐藏、缺失或不足的数据不做表现评价。不会凭空断言玩家挂机、作弊或现实身份。

**报告展示**：成功查询默认先发送一张本地生成的 PNG 战绩卡，再单独发送一条锐评。卡片包含玩家、区服、统计范围、核心指标、时间与来源信息，近期区间仍明确标注快照差分限制。渲染不调用 AI、浏览器或外部图片服务，不写入图片资源库；中文字体缺失或生成失败时自动回退为一条完整文本报告，锐评仍随后单独一条，不逐句拆散。参数错误、隐藏战绩、历史不足等只发一条文本提示，不生成看似成功的战绩图。

可设置 `$env:WOWS_STATS_IMAGE_ENABLED = 'false'` 改用完整文本报告，重启生效。图片渲染支持 headless Java，但运行环境需有中文字体（例如 Windows 微软雅黑或 Linux Noto Sans CJK SC）；没有可用中文字体时使用文本回退。NapCat/OneBot、HTTP 兼容接入及官方私聊沿用原发送通道；网页 API 新增有序 `messages` 数组表示报告和锐评，同时保留第一条消息的旧字段，独立网页聊天页已同步支持。已有普通聊天分段规则保持。

默认“战绩查询”规则通过 `wows_stats_v1` 一次性迁移新增（完全一致、优先级 30、`WOWS_STATS` 动作），已有同名规则不覆盖，管理页可改名、停用和删除；删除后重启不恢复。该动作命中时优先于资料路由，仍受规则排序、群总开关和普通群消息回复率控制。独立于 AI/Wiki/图片等开关，管理预览只解析参数，不调用外部接口。

已有玩家快照存于独立 H2 文件 `data/wows-player-stats.mv.db`，停用后保留且不打开，**不包含在管理页配置 SQL 导出中**；完整备份需停止服务后一起备份 `data/`。本次总开关同时关闭查询和后台采集，无需逐条删除触发规则。

## 本地数据和 SQL

使用内嵌 H2 数据库，通过 JDBC 参数化 SQL 保存，无需安装数据库服务器。以项目工作目录启动时：

```text
项目根目录/
├─ data/bot-config.mv.db       # 功能开关、规则、图片元数据
└─ uploads/images/            # 上传的图片，使用生成的唯一文件名
```

目录不存在时自动创建，重启后保留，已加入 Git 忽略规则。打包为 JAR 后，目录仍位于启动时的工作目录，而不是 JAR 内部。可以用 `BOT_STORAGE_DIRECTORY` 指定统一存储根目录。**备份时停止机器人，然后同时复制 `data/` 与 `uploads/`。** 同一存储目录只供一个机器人进程使用。

初始化建表 SQL 见 `src/main/resources/db/bot-schema.sql`。`ONEBOT_GROUP_REQUIRE_AT` 仅用于数据库首次创建时的默认值；之后以网页保存的设置为准，重启不会覆盖。

要从网页导出的 SQL 恢复，请先停止机器人，将对应的 `uploads/images/` 复制回存储根目录，再用 H2 的 `RunScript` 执行。以下示例适用于默认目录、H2 2.4.240，并使用 Maven 已下载的 H2 驱动：

```powershell
$h2Jar = Join-Path $env:USERPROFILE '.m2/repository/com/h2database/h2/2.4.240/h2-2.4.240.jar'
java -cp $h2Jar org.h2.tools.RunScript -url 'jdbc:h2:file:./data/bot-config' -user sa -script './almond-bot-config.sql' -charset UTF-8
```

恢复脚本会替换现有设置、规则、图片元数据、用户记忆和群聊记忆，请先保留旧数据备份。SQL 导出包含对话记忆及摘要，不包含图片二进制或连接密钥。

## 使用 NapCat 接入

1. 按 [NapCat 官方文档](https://napneko.github.io/guide/boot/Shell) 安装并登录用于机器人的 QQ 账号，让该账号加入目标群。
2. 在本项目目录用 PowerShell 设置环境变量并启动：

   ```powershell
   $env:ONEBOT_ENABLED = 'true'
   $env:ONEBOT_ACCESS_TOKEN = '替换为自己生成的随机长字符串'
   # 仅 AI 对话需要；ping、帮助和本地图片不需要此密钥。
   $env:DEEPSEEK_API_KEY = '你的 DeepSeek API Key'
   .\mvnw.cmd spring-boot:run
   ```

3. 在 NapCat WebUI 的网络配置中新建并启用 **WebSocket 客户端**（反向 WS）：

   | 配置项 | 值 |
   | --- | --- |
   | URL | `ws://127.0.0.1:8080/onebot/ws` |
   | Token | 与 `ONEBOT_ACCESS_TOKEN` 完全相同 |
   | 消息格式 | 数组（同时兼容 CQ 码字符串） |
   | 重连间隔 | 5000 毫秒 |

   只需这一条双向连接，不需要额外开启 HTTP API 或本项目主动连接 NapCat。掉线后的重连由 NapCat 发起。NapCat 的 WebUI 登录 token 与此处 OneBot 连接 token 是不同配置。

4. 启动日志出现 `OneBot 反向 WebSocket 已连接` 后，私聊机器人发送 `ping`，应收到 `pong`。先在网页“群聊管理”配置并开启目标群，再在群里直接发送 `ping` 验证群聊。

项目与 NapCat 分开部署时，将 `127.0.0.1` 替换为项目可达的主机地址；Docker 容器中的 `127.0.0.1` 指向容器自身。通过反向代理接入时需转发 WebSocket Upgrade 和 Authorization 请求头，跨公网使用 WSS。

接口实现依据 [NapCat 网络通信文档](https://napneko.github.io/onebot/network) 和 [框架接入文档](https://napneko.github.io/use/integration)。其他实现若兼容 OneBot v11 的通用反向 WebSocket、消息事件和发送 API，也可配置连接同一地址；尚未逐个进行真实客户端验证。当前不支持 OneBot v12、独立 event/API 双连接或正向 WebSocket。

## 对话和关键词

群聊必须先在网页配置并明确开启机器人功能。未配置或关闭的群不回复任何消息，包括 @、帮助、关键词、图片、查询和 AI；新发现的群默认关闭。已开启群和私聊直接识别关键词，无需 `/` 或 @，长句包含关键词也可触发。普通对话无需任何前缀。

普通聊天和关键词回复直接发送内容，不引用原消息。仅当收到的消息明确 @机器人时，首段文本或首张图片回复才附带原消息引用，后续段落不再重复引用；@其他人、@全体或单纯引用某条消息不会触发引用回复。缺少原消息 ID 时直接发送内容。

文字回复按句号、问号、感叹号和换行拆分，一句发送一次；超过 200 个 Unicode 字符的单句优先在逗号、空格处分段，必要时按长度拆分。小数、常见英文缩写、网址、Markdown 链接和代码片段尽量保持完整，单个链接或代码块可超过 200 字。句子过多时改为合并分段，避免连续发送大量短消息。同一次 OneBot 回复各段顺序发送，每段发送前重查群开关；发送异常时停止后续内容，不另发错误提示。分段不增加模型调用次数，个人记忆仍按完整一轮保存，群记忆按实际发出的每条消息计数。Web 聊天页也按段显示，接口的原 `content` 字段保留完整回复，并新增 `parts` 数组。

### 群聊自动对话

启动后访问 `http://localhost:8080/admin/index.html#groups`，侧栏选择“群聊管理”。NapCat 连接时会读取群列表，新发现的群默认关闭；也可手动填写机器人 QQ 号与群号。若侧栏没有入口，请确认运行的是最新构建的 JAR，并按 Ctrl+F5 刷新页面。

点击“配置”，勾选“开启此群机器人功能”后保存即可生效。此群开关覆盖全部功能；关闭或移除配置后立即停止处理后续群消息。各功能还受网页“功能设置”的开关控制。图片与固定关键词无需 AI 密钥；自动聊天需要配置 `DEEPSEEK_API_KEY` 并开启 AI 总开关。群表单只配置开关及用量，不再配置 AI 昵称、关键词或触发模式。

已开启群中，普通文本直接自动对话，例如“我想吃什么”，无需问号、关键词或 @。已有关键词和图片回复优先，不消耗自动对话 AI 次数。@其他人的消息、纯链接和超长文本不会触发群聊自动 AI。升级会统一旧群触发模式，但不会开启原本关闭或未配置的群。

群聊配置中的“自动回复率”范围为 0–1，例如 `0.2` 表示每条普通群消息有 20% 的概率参与回复。`0` 时普通群消息完全不回复，`1` 时每条都参与；包含关键词的消息也受此概率控制。私信和 @机器人跳过概率判定。群聊总开关、功能开关和 AI 用量限制继续生效，模型失败仍保持静默。每条消息只抽取一次，未抽中的消息不匹配关键词、不调用模型、不消耗每日次数。新群及升级后的旧群默认值为 `1`，可逐群调整；配置持久化并包含在 SQL 导出中。

AI 默认每群冷却30秒、每天50次、输入500字符、输出256 Token，群聊请求默认携带该用户在本群最近3轮对话及长期摘要；最近轮数由群配置控制。群内个人记忆按机器人QQ＋群号＋用户QQ隔离，私聊另存，重启不清空。冷却与每日次数持久化，日期按北京时间，失败也计次，同群不会并发调用；本地关键词和图片回复不占AI额度。

AI 只发送最终成功生成的文本，不先发送“思考中”等等待消息。连接失败、超时、空内容或异常响应均保持静默，仅记录后台日志；失败请求不会追加到聊天上下文，群聊用量仍按尝试次数计数。

仅将明确开启群中符合条件的文本与有限上下文发送到配置的 DeepSeek API，不使用 AI 判断每条消息是否应回复。群配置与用量记录保存在项目根目录的 `data/bot-config.mv.db`，随管理页 SQL 导出一起备份；图片继续保存在 `uploads/images/`。群聊管理适用于 OneBot 接入（包括 NapCat）。

下面是保留在数据库中的规则，可在 Web 管理中改名、停用或删除。AI 指令、帮助、清除历史和 Wiki 规则升级后默认停用，正常聊天不依赖它们。

| 默认关键词 | 执行动作 |
| --- | --- |
| `ping` | 验证连接 |
| `help`、`帮助` | 查看帮助 |
| `AI 问题`、`AI对话 问题` | AI 多轮对话（也支持小写 `ai`） |
| `清除历史`、`重置对话` | 清空当前用户的对话 |
| `FF14Wiki 查询词`、`ff14 查询词`、`wiki 查询词` | FF14 Wiki 查询 |
| `打灰`、`香草马娘` | 本地表情图片 |
| `随机马娘`、`随机小马` | 调用原有网络图片服务 |

保留图片规则时，“今天一起打灰吧”触发图片；仅在显式启用 Wiki 规则和功能开关后，“帮我查一下wiki 光之战士”才执行查询。AI / Wiki 关键词与参数之间必须用空格分隔，完整保留后续内容；`AI你好` 不作为带参数关键词，`OpenAI` 等英文单词不会误匹配 `AI`。参数中的其他关键词不会额外执行第二个动作。默认“包含关键词”适合长句，已有“完全一致”规则保留原有匹配设置；若新建规则需覆盖已有规则，请提高其优先级。

### 用户记忆

NapCat / OneBot私聊使用 `qq:{机器人QQ}:{用户QQ}`；群内个人记忆使用 `group-user:{机器人QQ}:{群号}:{用户QQ}`。同一用户在不同群和私聊各自隔离，清除本群个人记忆不清其他群或私聊。旧共享记录保留在原qq空间，不混入新的群内个人记忆。Web会话与官方QQ OpenID使用独立命名空间。每轮成功生成的用户/机器人对话保存为一条记录；失败、空响应、未抽中回复率或关闭群不新增记忆，固定回复不占AI记忆。

每人达到 50 条记录（含已有摘要）时触发后台归纳，**50 是整理阈值，不再是阻止聊天的硬上限**。本次先使用已有记忆正常生成并提交回复，再启动后台模型任务；整理期间新问答继续持久化，可能暂时超过 50 条。成功后只把该任务覆盖的最旧记录原子替换为首条长期摘要，任务开始后追加的记录原样保留。后续达到阈值时合并旧摘要与新记录继续整理。

摘要请求默认开启深度思考，不联网搜索；答案基础预算为2048 Token，另加4096思考预算，总生成上限6144 Token，并要求摘要不超过 1200 个中文字符。只接受正常完整结束的非空结果（保存上限仍为4000字符）；超时、异常、空内容、截断或写库失败时保留全部原记录，**不阻止回答、不停止保存新问答**。同一记忆目标最多一个任务，失败或无额度时至少间隔60秒，在后续消息活动中再尝试；未完成任务在重启后不直接恢复，但原记录仍在，后续成功问答可再次触发。长记录按完整记录选择较小旧前缀批次归纳，不把未送入本次摘要的记录一并清除。

群聊触发的归纳额外计入该群每日 AI 次数，也检查群聊与 AI 总开关，不改变普通回复冷却时间。额度不足时保留原文并继续保存后续消息；前台普通回复优先完成。原有“清除历史”动作会清除该 QQ 用户在此机器人下的全部记忆和摘要，并使旧后台任务失效，避免清空后被旧摘要重新写回。记忆持久化在 `data/bot-config.mv.db` 的 `conversation_memory` 表，并随管理页 SQL 导出备份。私信请求携带最近最多50轮及已有摘要，群聊可在配置中将“携带近期对话”设为0–50轮，另附摘要；后台积压不会无限增加发送给聊天模型的近期上下文。

### 群聊记忆

NapCat / OneBot 按“机器人 QQ 号＋群号”独立保存群聊记忆，不同群、不同机器人互不混用。仅记录管理页明确开启的群。群成员每条发言和机器人每条发出的回复分别计为一条，100条作为后台整理阈值，包含发言 QQ、群名片或昵称、时间及机器人身份标记；关键词回复也会记录。未抽中自动回复率、冷却中或 AI 请求失败时，群成员发言仍会记录。图片、语音等只记录类型占位，不保存其链接、Base64 或进行内容识别；私信不写入群记忆。

达到100条后，在本次消息处理/回复提交结束后后台归纳，成功只替换任务覆盖的旧前缀为首条摘要，期间追加的新消息保留；以后达到阈值继续整理。归纳区分成员 QQ 与机器人，保留话题、约定、偏好和更正。它受群开关、AI开关和每日限额限制，额外消耗一次API调用，不占普通回复冷却。失败保留所有原文并继续追加，后续群消息可重试，失败尝试至少间隔60秒，群重试时间重启保留。群在整理期间关闭或移除配置时，不应用该任务的结果。归纳失败不在聊天中输出报错。

个人和群记忆共用独立的2线程后台池、最多128个排队任务；不占 OneBot 消息处理线程等待模型，也不在模型请求期间持有记忆锁。队列满时保留数据、等待后续消息重试。首次更新会自动移除旧库 ordinal 的50/100上限约束，保留非负约束；备份SQL同样支持整理期间的超额记录。为避免丢失记忆，摘要长期不可用或没有额度时不会直接删除原文，数据库可能持续增长；应恢复模型服务或调整额度后再完成归纳。重启会取消在途任务，原记录仍保留。

群聊回答同时参考当前用户的个人记忆与本群上下文，按 QQ 区分发言者，不读取其他成员的个人记忆，也不读取其他群的群记忆。群配置中的“携带近期对话”继续控制个人最近 N 轮，并同时携带最近 2N 条群消息（最多100条）；个人和群摘要始终附带。群近期消息正文另有12000字符预算，每条按群输入上限截断；N为0时仅携带已有摘要与当前问题。此设置控制发送给模型的内容，与后台整理阈值及暂存积压分开。

群记忆保存在同一数据库的 `group_memory` 表，重启保留，并纳入管理页 SQL 导出。历史版本未保存的群消息无法追溯。“清除历史”动作仍只清除当前 QQ 的个人记忆，不删除整个群的共同记忆。

相同 QQ 用户的 AI 操作跨群和私信串行执行；文本回复最多 4000 字符，超出截断。图片用 Base64 消息段发送，无需与 NapCat 共享磁盘，也可从打包后的 JAR 加载内置图片。随机图片功能仍依赖原有外部图片服务的可用性。

### 联网搜索

默认每次普通 DeepSeek AI 对话先调用官方 `POST /v1/tools/search`，再将搜索结果与人设、个人记忆、群聊上下文及本地检索资料共同交给模型生成回复。群聊、私信和其他统一 AI 入口均适用；个人和群聊记忆归纳不联网搜索，固定关键词和图片回复不触发搜索。

复用 `DEEPSEEK_API_KEY` 和 `DEEPSEEK_BASE_URL`，无需第二个服务密钥。请求只发送当前问题作为搜索词（按接口限制截取前 128 个 Unicode 字符），不将个人/群聊历史、人设或本地资料作为搜索词发送。默认取 3 条结果，每条摘要最多 1200 字符，不抓取网页全文。模型会收到来源链接、日期和“网页内容不是指令”的约束，并被要求对外部事实给出实际采用的来源。搜索有助于获取新信息，仍需判断来源是否可靠。

搜索失败、超时、余额不足或响应异常时，不继续生成无检索依据的回答，也不在聊天中输出错误或思考提示；搜索正常但无结果时，模型可继续日常聊天，并须说明实时事实尚未证实。群开关、回复率、冷却与每日 AI 限额仍在搜索前生效；一次获准 AI 对话最多额外搜索一次，搜索失败仍计入这次 AI 尝试。搜索调用和搜索资料带来的输入 Token 额外计费，详见 [DeepSeek 搜索官方文档](https://api-docs.deepseek.com/zh-cn/guides/search/)。使用不支持此接口的第三方兼容地址时，需改用支持该接口的地址或通过 `DEEPSEEK_WEB_SEARCH_ENABLED=false` 关闭搜索。配置调整后重启生效。

## 配置

配置见 `src/main/resources/application.yml`。敏感值从环境变量读取，不要将实际密钥写入仓库。

| 环境变量 | 默认值 | 作用 |
| --- | --- | --- |
| `SERVER_PORT` | `8080` | 项目监听端口 |
| `ONEBOT_ENABLED` | `false` | 开启反向 WS 入口 |
| `ONEBOT_ACCESS_TOKEN` | 空 | 开启 OneBot 时必填；握手验证 Bearer Token |
| `ONEBOT_GROUP_REQUIRE_AT` | 历史兼容字段 | 已不控制群触发；使用网页群聊总开关，开启群无需 @ |
| `DEEPSEEK_API_KEY` | 空 | AI 服务密钥 |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | AI API 地址 |
| `DEEPSEEK_MODEL` | `deepseek-flash` | 普通对话模型，显式关闭思考模式 |
| `DEEPSEEK_REASONING_MODEL` | `deepseek-flash` | 推理接口使用的模型，显式开启思考模式 |
| `DEEPSEEK_WEB_SEARCH_ENABLED` | `true` | 普通 AI 对话先联网检索；设为 `false` 关闭 |
| `DEEPSEEK_WEB_SEARCH_RESULT_COUNT` | `3` | 每次搜索携带的结果条数，范围 1–5 |
| `QQ_APP_ID` / `QQ_APP_SECRET` / `QQ_TOKEN` | 空 | 原有官方接口使用的配置 |

YAML 中 `onebot.path` 可修改入口路径；`onebot.timeout` 是 action 响应超时（毫秒，默认 30000）。开启但未配置 token 会启动失败；未启用时不注册 WS 路由。

DeepSeek 当前模型与调用格式以[官方 API 文档](https://api-docs.deepseek.com/api/create-chat-completion)为准。旧的 `deepseek-chat` / `deepseek-reasoner` 已在[官方更新公告](https://api-docs.deepseek.com/updates)中列明于 2026-07-24 停用。项目内部兼容这两个旧调用标识，向外发送时使用上述环境变量配置的当前模型名。普通聊天显式设置 `thinking.type=disabled`，避免默认思考模式占用群聊有限的输出预算。

现有 `/qq/ask` 和 `/web/send` 接口继续保留。只使用 OneBot 时无需申请官方 App ID。旧的 `onebot.host`、`port`、`reconnect-delay` 配置已被反向连接替代。

原有 Go-CQHTTP HTTP 接入作为兼容入口保留，默认关闭。仅在需要该模式时设置 `GOCQHTTP_ENABLED=true`、`GOCQHTTP_API_URL` 和 `GOCQHTTP_ACCESS_TOKEN`。事件 POST 到 `/gocq/event`，须携带 `Authorization: Bearer <token>`；API 请求使用 `POST /<action>` 和参数 JSON。HTTP 与 WS 共用关键词逻辑和群聊总开关；同一账号请选择一种传输，两个入口之间不做跨传输去重。本次主要验收反向 WebSocket。

### 资料库导入与检索

启动后访问 `http://localhost:8080/admin/index.html#knowledge`，在“资料库”中新建资料库，填写名称和多个检索关键词（逗号或换行分隔），导入 TXT 文件，再勾选启用。一个资料库可包含多个文件，各自独立匹配关键词。

- 长句包含关键词即可触发，英文不区分大小写。多个库同时命中时，仅选择匹配关键词最长的库；长度相同时选择最早创建的库，不混合其他库的内容。
- 处理顺序：群开关及回复率检查 → 已启用资料库 → 普通关键词规则 → 普通模型聊天。资料库生成回复仍需开启 AI，群聊的冷却、每日限额、输入输出限制、静默失败和引用规则继续生效。
- 在所选库内按中文双字词及英文词进行本地片段检索，最多发送 4 段、每段最多 1024 字符给项目配置的模型 API；不使用额外的向量模型接口，不整库发送。资料不足时提示模型说明不足，不跨库补充。检索预览只返回本地命中库和片段，不调用模型。
- 支持 UTF-8（含 BOM）、GB18030、带 BOM 的 UTF-16 文本；仅接收 `.txt`，单个最大 512KB，每库最多 32 个文件、总计 4MB。最多 100 个资料库，每库 1–50 个关键词。
- 原文件存放在项目存储目录 `uploads/knowledge/`；配置和可检索文本保存到 `data/bot-config.mv.db`。SQL 导出包含资料库及完整检索文本，恢复后即使没有原文件也能检索；原文件需要另外备份。删除文件或资料库会同时移除相应检索数据和本地原文件。
- 资料库由所有已允许聊天共享；仅已启用群聊会在回复时发送匹配资料片段给配置的模型，私信同样可触发。导入前请确认资料适合提供给这些用户及模型服务。


### 战舰世界全量本地快照

在项目根目录执行：

```powershell
python scripts/sync_wows.py
```

脚本从 `https://iwarship.net/wowsdb/index` 读取最新 WG 正式服（ASIA）版本，下载全量舰船详情、舰名和中文翻译。保留全部分类、模块配置和原始字段，不仅限于某几艘船。首次下载需要联网，成功后通过原子替换 `data/wows/current.json` 发布新快照；下载失败不替换当前快照。

原始响应、版本元数据和按舰船整理的 `ships.json` 一并存于 `data/wows/<快照目录>/`。这是外部数据快照，独立于 H2 配置库，不包含在配置 SQL 中，备份时另行保留 `data/wows/`。数据不会打进 JAR，运行时存储目录需指向该项目目录；使用其他 `bot.storage-directory` 时，下载也应加 `--storage-directory <相同目录>`。

可选 `--server RU`（Lesta 正式服）、`--server PT`（WG 测试服）或 `--server RUPT`（Lesta 测试服）。每次只激活所选服务器的一个版本，不混合服务器；旧快照保留，便于手动回退。站点前端接口发生变化时可能需要调整同步脚本。

进入 Web 管理的“资料库”页，可查看版本、舰船数、开关以及本地查询预览。聊天默认启用本地舰船检索（仍受 AI 开关、群开关、回复率和限额控制）；自建资料库命中时优先使用自建库，否则按舰船中文名、英文名、编号或站点拼音缩写匹配本地快照，例如“得梅因的主炮装填是多少”“比较大和与蒙大拿的射程”。一次最多查询三艘，过多或名称有歧义时要求补充舰名。

聊天与预览只读取本地文件，不访问源网站，也不会把全量数据库发送给模型。仅将当前舰船与问题相关的字段、服务器和版本传给配置的模型，生成遵循人设的回答。大批量排行、舰船筛选以及上一轮舰名的省略追问尚不属于结构化检索能力；使用完整舰名能准确检索。数据字段保留来源命名，未知单位不擅自换算，基础值与极限值分开。更新后刷新管理页面或收到新查询时自动读取最新快照，无需重启。


### @机器人与关键词输入

支持 @ 前后附带 QQ 常见的不换行空格、窄不换行空格、全角空格和首尾零宽填充；带参数关键词可以使用空格或中英文冒号，例如 `@机器人 AI 你好`、`@机器人 AI：你好`。`AI你好`、`wiki光之战士`仍不视为带参数命令，避免误匹配自然语言；英文关键词继续按单词边界识别。移除 @、引用或图片等消息段时保留文本间隔，不将两侧文字拼成新的关键词；原始群记忆保留原有内容记录方式。


### 分段回复发送顺序

OneBot反向WebSocket发送分段回复时，按顺序等待每段的API成功回执，再提交下一段。@对话的引用与第一段正文放在同一条消息头部，只引用一次；不再同时提交多段发送请求。任一段失败、超时或连接断开就停止余下内容，不自动重试，避免重复消息或只收到尾段。超时沿用 `onebot.timeout`（默认30秒）；等待发生在消息工作线程，不阻塞WebSocket接收回执与心跳。API成功回执是可验证的发送顺序边界，仍需以真实QQ客户端显示验证最终效果。


### DeepSeek 思考与表达学习输出

默认模型仍为 `deepseek-flash`。普通聊天默认同时开启深度思考和官方联网检索；内部记忆摘要/表达学习开启思考，但不对群样本或历史做网络搜索。模型只向聊天返回 `content`，不发送或保存 `reasoning_content`。

- `DEEPSEEK_THINKING_ENABLED=true`：思考总开关；原推理专用调用仍明确开启思考。
- `DEEPSEEK_THINKING_EFFORT=high`：支持low/high/max。
- `DEEPSEEK_THINKING_EXTRA_TOKEN_BUDGET=4096`：在答案基础预算上增加的生成总预算，范围1024–16384。此为总生成上限的增量，不是API保证单独预留给思考的独立配额。
- `DEEPSEEK_WEB_SEARCH_ENABLED=true`：普通对话先调用Search API；搜索失败仍按原逻辑跳过，避免假装获得实时资料。

开启思考后，群模型请求的 `max_tokens` 为群输出基础预算＋思考增量；群回复最终字符裁剪上限仍按原群配置执行，但API生成Token成本上限有所增加。无单独预算的私聊/Web请求也显式限制为2048＋4096。HTTP读取超时由30秒调整为120秒，以容纳思考耗时。

表达学习请求启用 `response_format: {"type":"json_object"}`，明确要求完整短JSON；兼容完整的json/无语言代码围栏及首部BOM，但不修补截断JSON、不接受附带解释或多个JSON对象。失败保留原风格与样本、沿用冷却/额度，不立即重试。日志额外包含请求thinking/search/json/max_tokens及学习失败阶段（request/parse/persist），不打印群样本或API密钥。


## X / Twitter 推文订阅

支持OneBot群聊及私聊；在群内必须先启用该群的机器人。按“机器人QQ＋群/私聊＋目标QQ”隔离订阅，同名不会跨会话覆盖。这里的关注是机器人本地订阅，不改变X账号的真实关注列表；不支持Web/其他HTTP接入的定时推送。

```text
推特关注 赛马娘 https://x.com/username
推特获取 赛马娘
推特取消 赛马娘
```

名称为1–40个文字/数字/下划线/短横线，不含空格；链接为x.com或twitter.com的账号主页（可带分享查询参数），不是单条推文或followers页面。三条指令可带@机器人，明确指令绕过随机自动回复率及AI/资料库路由；输出为单条纯文本，包含账号、时间、正文和原始推文链接，不调用AI、不执行推文中CQ码，不自动下载图片或视频。固定格式的外部原文转发不经过AI内容边界过滤，订阅来源应由使用者选择。

### 配置和启动

在[X开发者控制台](https://developer.x.com/)准备有用户名查询和用户时间线读取权限/额度的应用Bearer Token，在启动机器人程序的环境中设置，勿发送到QQ群或聊天记录：

```powershell
$env:TWITTER_BEARER_TOKEN = '<你的Bearer Token>'
$env:TWITTER_ENABLED = 'true'
$env:TWITTER_POLL_INTERVAL_MS = '900000'
# 然后从同一环境启动机器人；IDE运行则在其运行配置中设置环境变量。
```

模型的DeepSeek密钥不能替代X Token。未配置Token不执行网络轮询；服务器必须能访问https://api.x.com。数据源为官方只读 `GET /2/users/by/username/{username}` 与 `GET /2/users/{id}/tweets`，API权限和额度以X控制台为准。本地关注/取消不会调用X写接口。关闭TWITTER_ENABLED后停止抓取，但仍可用取消指令删除本地订阅。

### 检查与推送行为

- 默认15分钟触发一次独立后台检查，间隔范围60000–86400000毫秒；每轮最多处理20个到期订阅、单线程，不阻塞其他定时任务。每会话最多10个、全机器人100个，较多订阅按上次检查时间轮转，100个订阅时一次完整轮转可能需5轮。
- 添加时查询并记录当前最新推文为基线，不推送历史积压；即使没有可读推文也可订阅。手动获取重新查询当前最新一条，不改变自动推送游标。默认时间线包含账号自身发布、回复、转发等API可返回内容，不读取关注者列表或私密内容。
- 定时查询使用since_id，仅向当前订阅会话发送本轮最新一条；多条新文时不逐条补发、不分页补齐全量历史。保留长推文note_tweet正文，超长展示裁剪并保留原文链接；不保存推文全文档案。
- 只有对应OneBot账号在线、群仍启用才查询/推送；取消命令和检查按订阅锁协调，取消成功后不再检查。通知与聊天分段共用同目标发送锁，避免插入一段未发完的聊天；等发送回执成功才推进游标。
- 发送失败/超时保留游标，下一轮再尝试；无法保证跨进程崩溃、回执丢失时严格只发一次，极端情况下可能重复。401/403授权错误及429限流后全局暂停X请求15分钟，不高频重试，不向聊天泄露上游响应或Token。
- 订阅与游标存入data/bot-config.mv.db的twitter_subscription表并纳入管理页SQL导出；Token仅来自环境变量，不入库/不导出。删除群配置后对应订阅保留但不再检查，可重新启用群后取消。

接口依据：[用户名查询](https://docs.x.com/x-api/users/get-user-by-username)、[用户推文时间线](https://docs.x.com/x-api/users/get-posts)。未配置真实Token时，仅能通过模拟测试验证流程，实际可读账号范围取决于X API权限和服务器网络。
